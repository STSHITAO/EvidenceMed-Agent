# Medical-Agent-Java 产品规格

## 定位

面向科研、教学和医生辅助复核场景的多模态医疗问答 Agent。输入为医学影像、自然语言问题和可选病例上下文，输出为带可追溯证据、不确定性和安全提示的辅助回答，不替代临床诊断。

## 用户功能

1. 用户登录后提交 JPEG/PNG 医学影像、问题和可选会话 ID。
2. 系统识别问答意图、急症红旗和所需检索策略，返回回答、证据来源、风险等级和人工复核提示。
3. 同一病例在多轮对话中保留有限上下文；Redis 缺失时从 MySQL 恢复。
4. 管理员上传 PDF、Markdown、TXT 医疗知识；系统恢复医学指南的章节、段落、表格、图片与图注结构，管理员可查看入库状态并重建索引。
5. 管理员查询报告、Agent 步骤、协作事件、模型耗时和降级原因。
6. 用户可通过内置响应式 Web 页面完成图文咨询并查看证据、风险和 trace ID。

## 核心能力

1. Java Harness 统一负责输入校验、Agent 调度、持久化、工具后处理和 trace。
2. Java 逐页评估 PDF 文本层、扫描特征、版面与对象类型，按需调用 OCR，恢复阅读顺序、跨页对象和章节结构后再执行语义切块。
3. Java 执行 BM25 与 Milvus 混合检索，结合可选 HyDE 查询，通过 RRF 融合并调用 vLLM reranker。
4. Coordinator 通过共享任务黑板、依赖关系和能力认领动态调度；病例记忆、规则路由和 RAG 是系统任务，证据规划、医学推理和安全批判才是 Agent 任务。
5. Redis 保存短期 `caseBrief` 和最近消息，MySQL 保存完整历史、知识与审计数据。
6. 动态加载医疗 `SKILL.md`，对证据不足、急症红旗和影像质量问题实施安全门控。
7. 同一轮独立系统任务可并行执行；证据不足时派生一次检索规划，安全拒绝时派生最多两次回答修订。

## 医学 PDF 入库

1. 入库不是整本抽取纯文本，而是生成带页码、坐标、对象类型、章节路径和解析质量的结构化文档。
2. 每页独立判断文本层可靠性、扫描页特征、图片数量和可能的表格区域；数字原生文本优先，只有低质量页面或区域进入 OCR。
3. 阅读顺序按左栏、右栏和整宽区域恢复，重复页眉页脚、页码、版权行和排版换行在不破坏医学单位与符号的前提下清洗。
4. 标题、正文、表格、图片、图注和表注作为不同知识对象处理；表格保持行列语义，图片与邻近图注建立关联。
5. 相邻页面的未结束段落、同列结构续表以及跨页图注执行规则化合并，并保留原始页码范围。
6. 切块以章节和完整证据对象为边界；检索结果可回溯到文件、章节、页码、对象类型和坐标区域。
7. OCR、表格识别或部分页面失败时记录降级原因与质量分，不静默伪造结构；可提取内容仍允许进入受控索引。

## 非目标

- 不训练、不微调、不在 JVM 中加载 GPU 模型。
- 不给出确定性诊断、处方或替代急诊处置的建议。
- 不长期保存原始医学影像。
- 不把 OCR 文本直接视为无误事实；低置信度页面和关键表格必须支持人工复核。
